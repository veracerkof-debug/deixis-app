# Документация Deixis

Здесь всё, что нужно, чтобы понять приложение и продолжить работу без устных объяснений. Это относится
к программисту и к ИИ. Если чего-то нет в документах — это ошибка документации: допишите.

## С чего начать

0. [dev/STATUS.md](dev/STATUS.md) — **состояние работы**: что ждём от автора, что делать дальше. Новая сессия начинает отсюда.
1. [../README.md](../README.md) — что такое Deixis, три приложения, быстрый запуск.
2. [../CLAUDE.md](../CLAUDE.md) — жёсткие правила проекта (короче некуда).
3. [dev/WORKFLOW.md](dev/WORKFLOW.md) — как работать: роли, правила подробно, отправка, выпуск, отчёт автору.
4. [dev/GLOSSARY.md](dev/GLOSSARY.md) — словарь: слово интерфейса → класс в коде.
5. [../ARCHITECTURE.md](../ARCHITECTURE.md) — устройство целиком: роли устройств, файлы и трансляция, сеть, форматы, стабильность.
6. [dev/CODEMAP.md](dev/CODEMAP.md) — карта кода: каждый модуль и файл, тесты, «где искать…».
7. [dev/KNOWLEDGE.md](dev/KNOWLEDGE.md) — разборы сбоев, неочевидные решения, открытые вопросы. **Прочесть
   перед правкой «странного» места.**

## Для ИИ-помощника: короткий маршрут

- Задача про поведение пользователя → `SCREENS.md` → `dev/GLOSSARY.md` → нужный `dev/*.md` → код по `dev/CODEMAP.md`.
- Задача «не работает у автора» → `dev/KNOWLEDGE.md` (может, уже разобрано) → попросить журнал
  («Настройки» → «Диагностика» → «Отправить файлом») → `dev/DESKTOP.md`/`dev/ANDROID.md`.
- Любая правка сети → `dev/PROTOCOL.md`, раздел о совместимости: старые пульты и экраны должны продолжать работать.
- Перед отправкой → `dev/WORKFLOW.md`, разделы 4–5.
