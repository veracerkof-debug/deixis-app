## Следующие шаги (по приоритету)

1. **Зал без монитора** после виртуального монитора (Linux, Мак: при выходе он убирается, а при следующем
   запуске может не создаться — единственный монитор остаётся выключенным под зал). Риск высокий.
   [KNOWLEDGE.md §3.1](KNOWLEDGE.md).
2. **«Входы» висят до 3 минут**, пока Windows ждёт окна прав при создании виртуального экрана (блокировка
   `DesktopCapture.select()`). Риск высокий. [KNOWLEDGE.md §3.1](KNOWLEDGE.md).
3. **AirPlay в сборке для Google Play** остаётся в APK (нарушение правила лицензий CLAUDE.md). Нужно перед
   любой сборкой для Play: вынести AirPlay так, чтобы R8 или flavour его вырезал, и проверить сборкой
   `-Pdeixis.store=play`.
4. Остальные риски из [KNOWLEDGE.md §3](KNOWLEDGE.md): совместимость enum (`coerceInputValues`), строки окон
   компьютера и экрана Android мимо переводов, `CastOutput` без обработки отказа и др.
