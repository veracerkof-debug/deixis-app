# Отчёт ночных проверок

Формат: что найдено → что сделано (коммит) или предложение на решение автора.

## Исправлено и встроено

### Прогон 1 — главный экран телефона (сетлисты, предпросмотр/зал, библиотека, темы, слои)
- Падение: одна песня дважды в плейлисте Holyrics → дубль ключа строки на главном. Плейлист переносится без повторов, сетлист на главном показывается без дублей.
- Падение: листание предпросмотра у элемента без слайдов (пустой текст, место Библии без модуля).
- Писание в демо-сетлисте на первом запуске оставалось пустым до перезапуска: пустой результат больше не запоминается, пока модули Библии грузятся.
- «Убрать демо» удаляло свои песни и сетлисты с такими же названиями («Amazing Grace», «Объявления», «Демо») — теперь только демо-элементы (метка или совпадение содержимого); общие демо-файлы не стираются, пока есть другие профили; «Вернуть демо» не трогает свой пустой сетлист.
- Смена профиля во время показа: «Дальше» по презентации из прежнего профиля ничего не отправлял, песня меняла оформление посреди показа, слои поверх прежнего профиля нельзя было убрать — то, что в зале, теперь уходит вместе с оператором.
- Удаление элемента, который в предпросмотре/в зале: предпросмотр закрывается, показ в зале продолжается; уходят его оформление и следы (хэши, переводы).
- Отсчёт «дальше» не из сетлиста запускал в зал первый элемент сетлиста.
- «Заглавные» в своей теме не доходили до зала.
- «В зал» с правкой оформления на миг повторно отправлял прежний слайд (мигание, перезапуск видео).
- Сохранение темы из панели тем молча готовило её в зал со следующим «В зал».
- Файл, добавляемый во время смены профиля, попадал в другой профиль.
- «В сетлист» без выбранного сетлиста говорил «добавлено», но ничего не делал — теперь берётся сетлист на главном или создаётся «Сегодня».
- Числа вместо токенов (скорость значков связи, затемнение, цвета полноэкранного просмотра) — в токены.
- Встроено: импорт песен из открытых форматов ChordPro и OpenLyrics (свой разбор по спецификациям, без XXE) — через «Файл».

### Прогон 2 — Библия и Holyrics
- Сборка телефона после прогона 1 (два конфликта имён) — исправлена первой.
- Важное: встроенные Синодальный и KJV нумеровали послания по порядку KJV (Римлянам — 520), а в настоящих модулях MyBible Римлянам — 590, Иакова — 520. С настоящим модулем вторым переводом показывалась не та книга, Holyrics получал не ту книгу. Встроенные модули перенумерованы; нетронутая старая копия на устройстве один раз заменяется (по контрольной сумме); сохранённые места со встроенными переводами переводятся на новые номера; таблица книг для Holyrics — по номерам MyBible.
- Демо «Пс 22:1–4» показывалось рядом с KJV, а у KJV это другой псалом (нумерация Синодального сдвинута) — демо-псалом теперь одним переводом.
- Падение: поиск по переводу, который добавили заново или удалили, обращался к закрытому файлу; повреждённый модуль ронял открытие главы.
- Быстрые касания открывали не ту главу; смена перевода сбрасывала выбранный диапазон стихов до одного.
- Адреса «1 Коринфянам 13», «1-е Кор 13:4», «Ин 3 16», книги с узбекским апострофом — распознаются (раньше уходили в поиск по тексту).
- Поиск: «o'g'il», «o’g’il» и «oʻgʻil» — одно слово.
- Holyrics: два быстрых нажатия F8/F9/F10 больше не оставляют экран чёрным; стих отмечается «в Holyrics», только когда Holyrics его показал; повторное подключение не плодит соединения; «Отключить» не стирает выбор переводов и тем; тихое переподключение при запуске больше не вызывает в Holyrics уведомление о правах каждый раз.

### Прогон 3 — сеть, сопряжение, безопасность приёмника
- Серьёзное: сопряжённый пульт мог прочитать или удалить файл вне кэша приёмника (имя вида «../tokens.json» вместо хэша — в показе, веб-пульте, переводе PPTX). Теперь любое имя, кроме хэша, отклоняется.
- PIN из четырёх цифр подбирался перебором из той же сети за минуты. Теперь после пяти ошибок PIN меняется и попытки не принимаются 30 секунд, каждый следующий раз вдвое дольше (до 10 минут); подбор становится невозможным. Сообщение на пульте говорит, что подождать.
- Телефон переставал переподключаться навсегда, если экран не ответил за 10 секунд после соединения (ошибка ожидания принималась за отмену). Теперь — обычный обрыв, переподключение идёт.
- Один файл с неверно заявленным огромным размером опустошал весь кэш приёмника, включая то, что на экране. Теперь такой файл отклоняется сразу, а показ, следующий слайд, наложения и логотип не вытесняются никогда (и старая очистка по времени их тоже не трогает). Загрузки из браузера учитываются в объёме кэша.
- Медленная загрузка с одного iPhone (экран погас) задерживала загрузки со всех остальных — теперь замок на каждую загрузку свой.
- Память: до входа по токену и у зрителей кадр ограничен 64 КБ (было 8 МБ на любое чужое соединение).
- Звук трансляции: раньше три неудачных подключения (экран ещё загружался, Wi-Fi переключился) выключали звук до конца трансляции. Теперь звук выключается только если экран действительно его не знает (старая версия), иначе возвращается вместе с картинкой. Слишком длинный кусок звука (больше 40 мс) не играется — он задержал бы звук в зале.

### Прогон 4 — компьютер: окна вывода, видео, трансляция, перевод PPTX
- Серьёзное: если видео не запускалось (нет VLC, ошибка файла, трансляция без FFmpeg и VLC), в зал выводился экран сопряжения — PIN, QR и адрес; любой в зале мог подключиться. Теперь под видео и вместо незапустившегося видео — чёрный кадр.
- Выпавший кабель проектора переносил зал на монитор оператора: окно во весь экран накрывало пульт, видео играло там со звуком. Теперь, если второй монитор был, оставшийся монитор пульта сам залом не становится (компьютер-экран с одной ролью «Экран» — как прежде).
- При двух мониторах зала: если отключить первый, видео на втором шло без звука. Теперь звук переходит к новому главному монитору.
- Сбой быстрой трансляции мог вернуть картинку трансляции поверх «Чёрного»/«Логотипа» (брал старое состояние) — теперь берётся текущее.
- Утечка: каждое переключение окна (Esc/F11, смена мониторов) оставляло в памяти экземпляр VLC. Двойное освобождение VLC при выходе (автоустановка обновления) могло ронять программу — освобождение теперь однократное.
- Быстрое листание тяжёлого PDF и обратный отсчёт с долями секунды на 4K копили очередь отрисовок и отставание зала — устаревшие кадры больше не рисуются.
- Перевод PPTX: при зависании LibreOffice оставался висеть процесс soffice.bin; на Windows настройки PDF доходили до LibreOffice без кавычек (не читались). Исправлено.
- «Что нового» после обновления больше не открывается поверх зала на компьютере-экране с одним монитором.
- Утечка памяти декодера FFmpeg, если декодер не открылся.

### Прогон 5 — ТВ, HDMI, DLNA, трансляция с телефона
- Серьёзное: после любого прошлого падения (даже разового сбоя видео посреди показа) Deixis TV при следующем запуске выводил в зал белый текст ошибки во весь экран и не показывал слайды, хотя приёмник работал. Теперь экран запускается как обычно, а причина сохраняется в файл для отчёта; экран ошибки — только если не запустился сейчас.
- Если на ТВ стоят и Deixis TV, и универсальный Deixis, второй экран не мог занять порт: универсальное приложение падало по кругу, Deixis TV оставался без связи. Теперь занятый порт заменяется свободным (адрес в QR и в поиске по сети — настоящий).
- Случайное «Назад» на пульте ТВ убирало показ из зала. Теперь экран зала закрывается только двойным «Назад» за 2 секунды (добавлено в карту жестов DESIGN.md).
- Повторный запуск трансляции экрана во время идущей обрывал обе и оставлял висеть кодировщик. Теперь прежняя аккуратно останавливается.
- Сбой кодировщика видео (поворот экрана, другое приложение забрало кодировщик) ронял приложение или замораживал кадр в зале, а телефон показывал «идёт трансляция». Теперь трансляция честно заканчивается: в зале чёрный, на телефоне — причина. Неудачный старт больше не оставляет кодировщик занятым.
- DLNA: быстрое листание перемешивало команды телевизору, он оставался на более раннем слайде — теперь команды по одной, и устаревшая не отправляется. Поиск телевизоров каждые 20 секунд оставлял открытое сетевое соединение — теперь закрывается.
- Смена разрешения HDMI (1080p↔4K, другой проектор) пересоздавала экран: видео начиналось сначала, трансляция на миг чернела. Исправлено.
- Кодировщик трансляции сверен с scrcpy: уже настроен так же (realtime, низкая задержка, повтор кадра, Baseline без B-кадров, размеры кратны 16).

### Прогон 6 — веб-пульт (iPhone), страница зрителей, веб-демо
- Подделки через имена файлов, песен, тексты Библии (XSS) — не найдено: всё экранируется.
- Серьёзное: уже сопряжённый iPhone, открывший старый QR-код (PIN в нём к тому времени сменился), терял сопряжение — неверный PIN стирал рабочий токен. То же при паузе после чужих попыток подбора. Теперь сначала проверяется сохранённое сопряжение, PIN из QR — только если экран его не знает; токен стирается только когда экран сказал «не знаю такого». Устаревший PIN убирается из адреса и больше не считается неверной попыткой при каждом обновлении страницы.
- Загрузка файла с iPhone обрывалась после первого же пропадания Wi-Fi (повтор сам падал без сети). Теперь до пяти повторов с докачкой; отказ экрана (нет прав, слишком большой файл) сообщается сразу, без 12 секунд ожидания.
- Пробел на выбранной строке списка (клавиатура, VoiceOver) открывал строку и одновременно выводил следующий слайд в зал. Исправлено.
- Сообщение о паузе после попыток PIN больше не обещает «полминуты» (пауза растёт).
- Страница зрителей: без обращения на «вы» в трёх языках.
- Пульт отдаётся с Referrer-Policy: no-referrer (ссылки на файлы несут токен).
- Уже было и проверено: ManagedMediaSource для iPhone, догон отставания, Wake Lock и видео против сна экрана, переподключение по pagehide/pageshow/visibilitychange.

## На решение автора (сомнительное, крупное)

### Из прогона 1
- Один размер текста на всю песню (как в Quelea): слайды не «прыгают» размером. Меняет вид всех песен — нужно ваше «да».
- Автолистание объявлений по кругу (каждые N секунд) для своих текстов, как у FreeShow/Holyrics.
- Вид «Сцена» с выбираемой раскладкой (текущий, следующий, часы, таймер, заметки) — сейчас раскладка одна.
- Повторы одной песни в сетлисте (реприза в конце): сейчас сетлист хранит элемент один раз; чтобы разрешить повторы, нужна перестройка порядка и ключей.
- Запись хэшей/фонов, которые досчитываются после смены профиля, в прежний профиль (сейчас — в открытый; редкий случай).

### Из прогона 2
- Сопоставление стихов Синодальный ↔ KJV (Псалмы, Иоиль, Малахия, Рим 16 и др.) по данным Copenhagen Alliance (данные CC BY-SA 4.0 — отдельным файлом с указанием авторства): для второго перевода рядом и для Holyrics. Без этого Синодальный рядом с KJV в Псалмах расходится на псалом.
- Импорт модулей Библии других форматов: Zefania XML и OpenSong XML (просто, 1–2 дня), MySword (1 день), USFM/USX для текстов eBible (общественное достояние). Узбекский «Muqaddas Kitob» — авторский текст IBT, встраивать нельзя, только импорт своего модуля.
- Таблицы названий книг на русском/английском из openbibleinfo (MIT) + узбекские вручную; диапазоны через главу «Ин 3:16–4:2» и списки «Ин 3:16,18».
- Полнотекстовый поиск с основами слов (Snowball, BSD) — находить «любовь» по «любви».
- Повторы песни в плейлисте Holyrics (реприза) сейчас сводятся к одной — из-за устройства сетлистов (см. прогон 1).
- Holyrics «Триггеры»: Holyrics сам может сообщать Deixis о смене стиха/плейлиста (POST в Deixis) вместо опроса раз в полсекунды.

### Из прогона 3
- Главное по безопасности: связь пульт↔экран идёт открытым HTTP, PIN и постоянный токен видны всем в той же сети Wi-Fi. Предложение: TLS с самоподписанным сертификатом и запоминанием отпечатка (как KDE Connect, LocalSend, Syncthing); отпечаток — в QR и при вводе PIN. Зрители остаются на HTTP (им прав не нужно). Меняет протокол — нужно решение.
- PAKE (SPAKE2 или J-PAKE из BouncyCastle, лицензия MIT-подобная): PIN нельзя подобрать даже по перехваченному трафику. Вместе с TLS.
- Ретранслятор на компьютере: если в сети появился «экран» с тем же id по новому адресу, компьютер сам отправляет ему токен. Поддельный экран так получит токен настоящего. Исправление — проверка «запрос–ответ» вместо отправки токена (меняет протокол) или подтверждение оператором при смене адреса.
- Токен в адресе ссылок на файлы веб-пульта (`?t=`) попадает в историю браузера. Замена — короткоживущие подписанные ссылки на один файл.
- Opus вместо несжатого звука (MediaCodec на Android, libopus BSD): в 15–20 раз меньше трафика, +5–10 мс задержки. Полезно на слабом Wi-Fi.
- Зрители: WebCodecs (минимальная задержка, но нужен HTTPS) или jmuxer (MIT) — надо сравнить с нынешним fMP4 по задержке.
- Обнаружение экранов вторым способом, как у LocalSend (UDP multicast), — где роутер режет mDNS.

### Из прогона 4
- JODConverter (Apache-2.0): держать LibreOffice запущенным заранее — перевод PPTX за доли секунды вместо 3–10 с холодного старта. Новая зависимость — нужно «да».
- Аппаратное декодирование трансляции (d3d11va / VideoToolbox / VAAPI в том же FFmpeg) и показ YUV шейдером (LWJGL, BSD-3, или Skia RuntimeEffect в Compose) без перевода в BGR — меньше нагрузка на процессор на 4K. Сейчас Full HD декодируется за ~3 мс, острой нужды нет.
- PDFium (BSD-3/Apache-2.0, бинарники bblanchon/pdfium-binaries; обёртка jpdfium MIT требует Java 25) — в несколько раз быстрее PDFBox. Вместе с этим — отрисовка следующей страницы заранее.
- Звук: OpenAL Soft через LWJGL (LGPL/BSD) — 10–20 мс на Windows вместо 50–100 мс у DirectSound в javax.sound.
- Обновления: подпись установщиков (macOS Developer ID + нотаризация, Windows через SignPath Foundation бесплатно для открытых проектов) — без неё SmartScreen и Gatekeeper пугают; Sparkle/WinSparkle (MIT) как альтернатива своему механизму.
- Microsoft Office через COM (Windows): зависший PowerPoint не дочерний процесс, его не остановить вместе со сценарием — следующие переводы ждут до 180 с. Нужен поиск и закрытие процесса по имени — опасно для открытых документов пользователя, поэтому на решение.
- Linux: автоустановка обновления при выходе ждёт 60 с (установщик Linux лишь открывает центр приложений) — лучше на Linux не предлагать «установить при выходе».

### Из прогона 5
- DLNA: перед каждым слайдом посылается Stop (часть телевизоров иначе не меняет картинку), из-за этого некоторые ТВ на миг показывают свой чёрный экран или плеер. Можно сначала пробовать без Stop и посылать его только при ошибке — но тогда на «упрямых» ТВ слайд не сменится. Нужна проверка на ваших телевизорах.
- Когда окно экрана на ТВ ушло в фон (кнопка «Домой»), телефон об этом не знает и считает, что слайд в зале. Предложение: экран сообщает пульту «не виден» и возвращается сам при следующем слайде.
- Тексты уведомлений трансляции и экрана ошибки ТВ — пока только по-русски (перевод на узбекский и английский — вместе с общим переводом телефона).
- Цвет и размеры экрана ошибки ТВ — литералами, не токенами (экран виден только при невозможности запуска).
- FCast (FUTO, MIT, fcast.org) — открытый протокол «как Cast» без Google: приёмники для Android/Linux/Windows; кандидат для версии не из Play.
- AirPlay-приёмник на компьютере (UxPlay, GPL-3.0) для iPhone и Mac: по лицензии совместим, но код чужого приложения и обратная разработка FairPlay — только как внешняя программа по желанию пользователя.
- H.265 для трансляции на свой компьютерный приёмник — вдвое меньше трафика; зрителям в браузере — только H.264.
- Запасной путь через adb + scrcpy-server (Apache-2.0, отдельной программой) — «режим техника» по USB или беспроводной отладке; много шагов для обычного пользователя.
- Перезапуск кодировщика с меньшим разрешением при сбое (1920 → 1600 → 1280), как в scrcpy; запрос ключевого кадра при новом зрителе уже есть.

### Из прогона 6
- Веб-демо грузит pdf.js и qrcode-generator с cdnjs (Cloudflare) без проверки целостности — посетитель демо обращается к стороннему серверу. Предложение: класть обе библиотеки (Apache-2.0 и MIT) в демо при сборке.

- Сообщения сервера (ошибки загрузки и т. п.) приходят в веб-пульт по-русски и для узбекского и английского — нужен переход на коды ошибок с переводом в пульте; там же убрать «покажите».
- Контраст в светлой теме ниже AA: второстепенный текст (3,3:1) и белый на кнопке «В зал» (4,3:1); кнопка «В зал» 26 px, образцы цвета 30 px, сегменты 32 px — меньше 44 px. Меняет вид — нужно «да».
- Отмена загрузки и несколько загрузок сразу со своим прогрессом.
- axe-core (MPL-2.0) с Playwright в CI — автоматическая проверка доступности страницы пульта в обеих темах.
- Демо: версии в именах файлов (после выкладки старые hub.js/shim.js из кэша могут работать с новой страницей).
- Протокол tus (MIT) как образец докачки; reconnecting-websocket и NoSleep.js не нужны — своё уже покрывает.

## Открытые проекты и алгоритмы, изученные по ходу

- FreeShow (GPL-3.0): раскладки «Сцены», таймеры слайдов, очистка по слоям. Идеи, без кода.
- OpenLP (GPL-3.0-or-later): поиск по первой строке, порядок куплетов «V1 C V2 C», заметки к пунктам служения.
- Quelea (GPL-3.0): свой Android-пульт, импорт многих форматов, один размер на песню.

- Видео по сети: OMT (MIT, без Java-привязок), SRT (MPL-2.0), WebRTC (BSD-3) — для зрителей в браузере.
