# Как написать викторину для Deixis (инструкция для нейросети)

Отдайте этот файл модели вместе с темой урока. Результат — один JSON-файл с именем `что-нибудь.deixis-quiz.json`.
Deixis откроет его в плеере и проведёт игру; перед открытием файл проверяется. Подробный разбор — [FORMAT.md](FORMAT.md),
готовый пример — [example.deixis-quiz.json](example.deixis-quiz.json).

## Правила, которые нельзя нарушать

1. Ответ — только JSON, без пояснений вокруг и без блоков markdown (никаких ```).
2. Корень — объект с полями `format: "deixis-quiz"`, `version: 1`, `title`, `questions`.
3. Типы вопросов — только `single` (один верный), `multiple` (несколько верных), `truefalse` (верно/неверно).
   Другие типы (`fill`, `order`, `match`, `input`, `poll`, `wordcloud`) пока не работают — не использовать.
4. `id` вопросов и вариантов — латиница, цифры, `_`, `-`, до 32 знаков, уникальные внутри своего списка
   (`q1`, `q2`; у вариантов `a`, `b`, `c`).
5. `single`: ровно один вариант с `"correct": true`. `multiple`: два и больше с `"correct": true`.
   Вариантов от 2 до 8. У варианта `"correct": false` не пишут — это значение по умолчанию.
6. `truefalse`: поле `"answer": true` или `false`, поля `options` нет.
7. Текст вопроса — до 1000 знаков, варианта — до 300, пояснения — до 2000. Название — до 200.
8. Верный вариант не должен быть самым длинным или всегда стоять первым: перемешивайте позиции.
9. Картинок не придумывать. Поле `image` и блок `assets` не писать, пока автор не просит и не даёт файлы.
10. Язык текста — язык автора; в поле `language` — `ru`, `uz` или `en`.

## Поля

Файл: `format`, `version` (1), `title`, `language` (по умолчанию `ru`), `description`, `settings`, `questions`.

`settings` (всё необязательно): `passPercent` (0–100, 0 — без зачёта), `shuffleQuestions`, `shuffleOptions`,
`showExplanations`, `defaultTimeLimitSec` (5–600, секунд на вопрос).

Вопрос: `id`, `type`, `text`, `points` (0–1000, по умолчанию 1), `timeLimitSec` (5–600),
`explanation` (что показать после ответа), `options` (для `single`/`multiple`), `answer` (для `truefalse`),
`scoring` (для `multiple`: `"all"` — очки только за точный набор, `"partial"` — по доле верных, лишние вычитаются).

Вариант: `id`, `text`, `correct`.

## Как писать хорошие вопросы

- Один вопрос — одна мысль. Формулируйте так, чтобы верный ответ не угадывался по грамматике.
- Неверные варианты правдоподобны и одной длины с верным. Не использовать «все перечисленное» и «ничего из перечисленного».
- К каждому вопросу — короткое `explanation` (одно-два предложения): почему верно именно это.
- В `multiple` напишите в тексте, что верных несколько («Выберите все…»).
- Сложность растёт от начала к концу. Для класса — 8–15 вопросов, `defaultTimeLimitSec` 20–30.

## Проверьте перед выдачей

Каждый вопрос: уникальный `id`; тип из трёх; у `single` один `correct`; у `multiple` не меньше двух; у `truefalse` есть
`answer`; нет запятых после последних элементов; нет комментариев (в JSON их не бывает).
Deixis сообщит об ошибке с путём вроде `questions[2].options[1].text` — отдайте это сообщение модели, она исправит.
